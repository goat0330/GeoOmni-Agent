Final product state validated
-----------------------------
1. The obsolete intermediate meeting screen is removed from the meeting path:
   expert library -> collaborative response-plan / level-confirmation screen -> join
   is NOT used by v2.
2. The required path is:
   expert library -> 确认邀请 -> device join -> 应急会商室.
3. The expert-library dialog receives one inline required meeting-topic row.
4. Pre-meeting Smart Minutes opens directly on the right and uses empty/live states
   instead of generating fake final minutes before the meeting starts.
5. The device join step contains camera preview, microphone selection and camera selection.
6. The emergency meeting room starts with Smart Minutes closed.
7. Clicking the room's Smart Minutes button opens the same reusable right sidebar.
8. The final sidebar contains:
   - meeting overview
   - risk assessment summary
   - recommendations
   - responsibility items
   - edit minutes
   - send to responsible person
9. Only “结束会议” creates a final history record. “离开会议” does not create one.
10. Meeting history contains base information, final minutes and distribution state.

Design System alignment
-----------------------
- meeting-feature/meeting-suite.css starts with @geo-design-enforce.
- New Meeting Suite UI consumes existing --geo-* tokens.
- Existing .geo-ui-* primitives are reused for buttons, inputs, selects, textareas and checkboxes.
- No raw hex / rgb / hsl colors are present in enforced Meeting Suite CSS.
- No arbitrary pixel border-radius values are present in enforced Meeting Suite CSS.
- No second font-family stack is introduced.
- mirror-clean6 compiled front-end assets remain untouched.

Integration behavior
--------------------
- Original expertsCard list/search/pagination/invitation remains authoritative.
- “进入会商室” is normalized to “确认邀请”.
- “结束会话” is normalized to “取消”; the cancel action no longer invokes meeting-end semantics.
- Topic is persisted to meetingContext before entering device selection.
- Existing server participants are hydrated before creating a fallback meeting, preventing
  selected invitees from being discarded when a native active meeting id is unavailable.
- v1 -> v2 upgrade removes the old v1 AGENTS contract and installs the v2 contract.
